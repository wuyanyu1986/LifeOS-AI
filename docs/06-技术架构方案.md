# 技术架构方案

## 架构目标

- 先实现可运行的本地或半自动流程。
- 保证原始数据和结构化结果可追溯。
- 方便未来接入飞书、GitHub、数据库和前端应用。
- Agent Prompt 可版本化管理。

## 推荐技术栈

早期：

- Markdown 作为产品和 Prompt 文档载体。
- 本地脚本或轻量后端负责处理流程。
- 飞书文档作为知识库前端。
- GitHub 管理版本和 Issue。

后续：

- Node.js 或 Python 后端。
- SQLite 或 Postgres 存储结构化日记。
- 对象存储保存视频和音频文件。
- Web App 提供上传、查看、编辑和检索界面。
- 向量数据库支持语义检索。

## 模块划分

```text
interfaces/
  upload
  review
  search

services/
  transcription
  agent-orchestration
  memory
  content-generation
  feishu-sync

storage/
  raw-media
  transcripts
  structured-entries
  memory-cards
```

## 数据流

```text
Media File
  -> Transcription Service
  -> Diary Entry JSON
  -> Agent Orchestrator
  -> Structured Outputs
  -> Feishu Sync
  -> Memory Store
```

## 关键接口草案

### 创建日记

```http
POST /entries
```

### 获取日记

```http
GET /entries/{entry_id}
```

### 运行 Agent 流程

```http
POST /entries/{entry_id}/run
```

### 同步到飞书

```http
POST /entries/{entry_id}/sync/feishu
```

## 风险

- 视频和日记数据高度私密，需要默认本地优先或明确授权。
- Agent 输出可能过度推断，需要保留来源和置信度。
- 飞书 API 权限和文档结构需要稳定设计。
- 长期记忆可能积累错误，需要用户确认和可回滚机制。
